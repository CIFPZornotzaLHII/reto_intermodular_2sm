# Ideas de proyecto · SMR

Veinte ideas de partida. Todas tienen un cliente o una necesidad identificable y se pueden montar en las horas del
módulo apoyándose en lo que ya trabajáis en otros módulos. Podéis combinarlas, recortarlas o proponer otra: lo que no
cambia es que tiene que haber **un cliente, un plan y algo que funcione en la demo**.

Cómo elegir: coged una que os guste, buscad un cliente real (un comercio, una asociación, un departamento del centro,
una familia) y preguntadle qué le haría falta de verdad. El proyecto bueno sale de esa conversación, no de la lista.

| # | Idea | Qué es | Tecnologías del ciclo | Lo mínimo que tiene que funcionar |
|---|---|---|---|---|
| 1 | **Red segura para una pyme** | Diseñar y montar en Proxmox la red de una pequeña empresa: firewall, redes separadas (oficina / invitados), DHCP, DNS y servidor de ficheros. | Proxmox, firewall (OPNsense/pfSense), DHCP, DNS, Samba, Linux y Windows | Dos redes aisladas, un cliente de cada una conectando y accediendo a su carpeta compartida |
| 2 | **Copias de seguridad que se restauran solas** | Servidor de copias para un negocio o una familia: copia diaria automática, retención, informe por correo y restauración probada. | Linux, bash, rsync/Borg, cron, SMTP, RAID por software | Copia programada, restauración completa de un fichero borrado y un informe recibido |
| 3 | **WordPress para un negocio local** | Web de un comercio o asociación real en WordPress: alojamiento propio, HTTPS, copias y endurecimiento básico. | Apache/Nginx, WordPress, certificados SSL, backups, Linux | Web publicada en el servidor del aula con HTTPS, usuario editor para el cliente y copia automática |
| 4 | **Aula en 10 minutos** | Instalación desatendida y scripts de post-instalación para montar un puesto estándar (Windows o Linux) con todo el software del centro. | Instalación desatendida, PowerShell/winget o bash, imágenes, Clonezilla/Ventoy | Un equipo limpio queda listo para usar sin tocar nada, con el software y la configuración definidos |
| 5 | **Dominio Windows con actualizaciones centralizadas** | Pequeño dominio Active Directory con usuarios por departamento, directivas básicas y WSUS para las actualizaciones. | Windows Server, AD, GPO, WSUS, DHCP, DNS | Dos clientes unidos al dominio, inicio de sesión con roles distintos y actualizaciones aprobadas desde el servidor |
| 6 | **Monitorización del aula** | Un panel que vigila equipos y servicios del aula o de una pyme y avisa cuando algo cae. | Docker (Uptime Kuma/Zabbix), Linux, SNMP/ping, SMTP o Telegram | Panel con al menos cinco equipos o servicios, una alerta real al apagar uno |
| 7 | **Gestor de contraseñas corporativo** | Servicio de contraseñas compartidas para una empresa pequeña, con política de contraseñas y copia cifrada. | Docker (Vaultwarden) o KeePass compartido, SSL, backups, cifrado | Dos usuarios con cofres separados y uno compartido, acceso desde el navegador y desde el móvil |
| 8 | **Servidor de ficheros con RAID y permisos** | Servidor Samba con carpetas por departamento, RAID, cuotas y simulación de fallo de disco. | Linux, Samba, RAID (mdadm), permisos, SAI | Permisos que funcionan desde Windows y Linux; se quita un disco y el servicio sigue; se reconstruye |
| 9 | **Pantalla de avisos del centro** | Señalización digital: una pantalla en el hall que muestra avisos y horarios, gestionada por SSH desde una carpeta compartida. | Linux (Raspberry/mini-PC), SSH, bash, navegador en modo kiosco, Samba | La pantalla arranca sola en modo kiosco y cambia el contenido cuando se edita un fichero |
| 10 | **Inventario del aula** | Inventario automático de hardware y software de los equipos con scripts, volcado a una hoja de cálculo o a GLPI. | bash/PowerShell, hoja de cálculo avanzada, Docker (GLPI opcional) | Un script recoge los datos de todos los equipos y la hoja resume modelos, discos y software instalado |
| 11 | **Teletrabajo seguro con VPN** | Acceso remoto a la red de una pyme con WireGuard, clientes Windows/Linux/móvil y manual para los usuarios. | WireGuard, firewall, Linux, Windows, móviles | Un portátil fuera de la red accede a la carpeta compartida por la VPN; un cliente revocado deja de poder |
| 12 | **DNS con filtrado para la red del taller** | DNS/DHCP centralizado con bloqueo de publicidad y de sitios no deseados, con estadísticas. | Pi-hole/AdGuard (Docker o Linux), DHCP, DNS | Toda la red resuelve por el servidor; un dominio bloqueado no carga; estadísticas visibles |
| 13 | **Recuperación de datos y clonado** | Procedimiento y laboratorio para recuperar datos de discos dañados y clonar equipos, con protocolo escrito. | Linux, dd/ddrescue, TestDisk/PhotoRec, Clonezilla | Recuperación de ficheros de una imagen dañada preparada a propósito y clonado de un equipo |
| 14 | **Impresión centralizada** | Servidor de impresión con colas por aula o departamento, cuotas y clientes Windows y Linux. | CUPS, Samba, Linux, Windows | Dos clientes imprimen por el servidor en colas distintas; se ve el registro de trabajos |
| 15 | **Intercambio de ficheros con clientes** | Servidor FTPS/SFTP para que los clientes de una empresa suban y bajen documentos, con usuarios aislados y registro. | FTP/FTPS/SFTP, Linux, permisos, SSL, logs | Dos clientes con carpetas aisladas; transferencia cifrada comprobada con Wireshark |
| 16 | **Equipos reacondicionados para donar** | Diagnóstico, reparación, limpieza e instalación de un Linux ligero en equipos donados, con manual de entrega. | Montaje y mantenimiento, diagnóstico de hardware, Linux ligero, ofimática | Al menos dos equipos entregados funcionando, con ficha de diagnóstico y manual para el usuario |
| 17 | **Auditoría básica de la red del aula** | Inventario de puertos y servicios abiertos, debilidades encontradas, plan de corrección y reglas de firewall aplicadas. | nmap, Wireshark, firewall, Linux, Windows, buenas prácticas de seguridad | Informe antes/después con al menos tres debilidades corregidas y comprobadas |
| 18 | **Flota de móviles y tablets del centro** | Puesta a punto de una flota de dispositivos: configuración común, copias, seguridad y procedimiento de préstamo. | Android/iOS básico, cuentas, copias, gestor de contraseñas, ofimática | Tres dispositivos configurados igual, con bloqueo, copia y un documento de procedimiento |
| 19 | **Help desk con tickets** | Sistema de incidencias para el centro o una pyme: formulario, cola de tickets, categorías y tiempos de respuesta. | Docker (osTicket/GLPI), Linux, SMTP, Apache/Nginx | Un usuario abre un ticket por correo o web, un técnico lo atiende y se cierra con informe |
| 20 | **Servidor doméstico multimedia y de copias** | Para una familia: servidor con copias de los móviles, fotos compartidas y multimedia, accesible desde la red de casa. | Linux, Docker (Nextcloud/Jellyfin), Samba, RAID, copias | Un móvil sube fotos automáticamente, se ven desde la tele/PC y hay copia en segundo disco |
